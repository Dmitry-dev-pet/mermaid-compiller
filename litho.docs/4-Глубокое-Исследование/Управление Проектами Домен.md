# Управление Проектами Домен: Техническая Документация

## Обзор домена

**Управление Проектами Домен** — это критически важный компонент платформы **mermaid-langgraph**, отвечающий за полный жизненный цикл проектов диаграмм Mermaid: создание, сохранение, загрузку, редактирование, удаление и восстановление. Домен обеспечивает сохранность пользовательских сессий между перезагрузками браузера, поддерживает многопользовательские сценарии и является основой для стабильной работы всех остальных модулей системы.

Домен реализован как **модульная архитектура с разделением ответственности**, состоящая из двух поддоменов: **Хранилище Проектов** (бизнес-логика и доступ к данным) и **Управление Интерфейсом** (пользовательский интерфейс). Он полностью интегрирован в фронтенд-приложение и не требует серверной инфраструктуры, что делает платформу автономной и легко развертываемой.

## Архитектура и компоненты

### 1. Хранилище Проектов (Core Storage Layer)

Этот поддомен представляет собой **надежный, асинхронный и типизированный слой доступа к данным**, реализованный с использованием современных веб-технологий. Он абстрагирует сложность работы с браузерными хранилищами и предоставляет чистый, предсказуемый API для остальных компонентов системы.

#### Ключевые компоненты:

- **`types.ts`** — Глобальные типы данных
- **`db.ts`** — Низкоуровневый интерфейс к IndexedDB
- **`store.ts`** — Сервис с бизнес-логикой и кэшированием
- **`useProjects.ts`** — React-хук для интеграции с UI

#### Типизация данных (types.ts)

Система использует строгую типизацию TypeScript для обеспечения целостности данных. Основные интерфейсы:

```typescript
export interface HistorySession {
  id: string; // Уникальный идентификатор проекта
  createdAt: number; // Время создания (timestamp)
  updatedAt?: number; // Время последнего обновления
  title?: string; // Человеко-читаемое имя проекта
  nextStepIndex: number; // Индекс следующего шага истории
  currentRevisionId: string | null; // ID текущей ревизии кода
  settings?: SessionSettings; // Настройки редактора и ИИ
}

export interface SessionSettings {
  appState: AppState; // Состояние UI (размеры, темы, вкладки)
  aiConfig: AIConfig; // Конфигурация ИИ-ассистента (модель, ключи)
  modelParams?: Record<string, number | string | boolean | null>; // Параметры LLM
}

export interface TimeStep {
  id: string; // Уникальный ID шага
  sessionId: string; // Ссылка на проект
  index: number; // Порядковый номер шага в проекте
  type: TimeStepType; // Тип действия: 'chat', 'manual_edit', 'fix' и т.д.
  createdAt: number;
  messages: Message[]; // История диалога с ИИ
  currentRevisionId: string | null; // Ревизия на момент шага
  meta?: StepMeta; // Дополнительные метаданные
}

export interface DiagramRevision {
  id: string;
  sessionId: string;
  createdAt: number;
  createdByStepId: string; // Ссылка на шаг, который создал эту ревизию
  parentRevisionId: string | null; // Родительская ревизия (для отката)
  mermaid: string; // Текущий код диаграммы
  diagnostics?: RevisionDiagnostics; // Статус валидации
}

export interface RevisionDiagnostics {
  isValid: boolean;
  errorMessage?: string;
  errorLine?: number;
}
```

#### Низкоуровневый доступ к базе данных (db.ts)

Использует **IndexedDB** — современное браузерное хранилище с поддержкой транзакций и индексов. Реализует паттерн `withTx` для безопасного выполнения операций:

```typescript
export const withTx = async <T>(
  stores: string[], // Список объектных хранилищ
  mode: IDBTransactionMode, // 'readonly' или 'readwrite'
  fn: (tx: IDBTransaction) => Promise<T> | T
): Promise<T> => {
  const db = await openHistoryDb(); // Открывает или создает базу данных
  const tx = db.transaction(stores, mode);
  const result = await fn(tx);
  await txDone(tx); // Ждет завершения транзакции
  return result;
};
```

База данных содержит три объектных хранилища:
- `sessions` — хранит метаданные проектов (название, дата, настройки)
- `steps` — хранит историю действий пользователя (каждый чат, редактирование, исправление)
- `revisions` — хранит версии кода диаграммы (для отката и сравнения)

Индексы (`byCreatedAt`, `bySessionId`, `bySessionIndex`) обеспечивают быструю выборку данных.

#### Сервис управления состоянием (store.ts)

Этот модуль является **ядром логики хранилища**. Он реализует все основные операции:

- **`createSession()`** — Создает новый проект с уникальным ID, инициализирует его настройками и сохраняет в IndexedDB. Автоматически устанавливает его как активный.
- **`getSession(sessionId)`** — Загружает проект по ID. Возвращает `null`, если проект не найден.
- **`listSessions()`** — Возвращает список всех проектов, отсортированных по дате обновления (новые сверху).
- **`renameSession(sessionId, title)`** — Обновляет название проекта.
- **`updateSessionSettings(sessionId, settings)`** — Сохраняет текущие настройки редактора и ИИ.
- **`recordStep(args)`** — Ключевая функция, которая записывает каждое действие пользователя (ввод кода, запрос к ИИ, исправление) как шаг (`TimeStep`) и, при необходимости, создает новую ревизию (`DiagramRevision`) кода диаграммы. Это обеспечивает полную историю изменений.
- **`ensureActiveSession()`** — Гарантирует, что всегда существует активный проект. Если активный проект не найден (например, после очистки кэша), создает новый.

#### Резервное хранилище и идентификация сессии

Для обеспечения надежности используется **резервный механизм на основе `localStorage`**:

```typescript
export const ACTIVE_SESSION_KEY = 'dc_active_session_id';

export const getActiveSessionId = () => {
  try {
    return localStorage.getItem(ACTIVE_SESSION_KEY);
  } catch {
    return null;
  }
};

export const setActiveSessionId = (id: string) => {
  try {
    localStorage.setItem(ACTIVE_SESSION_KEY, id);
  } catch {
    // ignore
  }
};
```

При создании нового проекта его ID сохраняется в `localStorage`. При запуске приложения система сначала проверяет `localStorage` на наличие активного проекта, а затем загружает его из IndexedDB. Это обеспечивает **быстрое восстановление сессии** и **отказоустойчивость** в случае сбоев IndexedDB.

### 2. Управление Интерфейсом (UI Layer)

Этот поддомен реализует **пользовательский интерфейс управления проектами** через компонент `ChatProjects.tsx`.

#### Основные функции интерфейса:

- **Создание нового проекта**: Кнопка "New" вызывает `startNewProject()` из хука `useProjects`, который инициализирует пустой проект и сбрасывает состояние редактора и чата.
- **Открытие проекта**: Клик по названию проекта вызывает `openProject(sessionId)`, который загружает все данные (код, настройки, историю) и обновляет состояние приложения.
- **Переименование проекта**: Поддерживает инлайн-редактирование. При двойном клике или нажатии на иконку карандаша (`Pencil`) появляется поле ввода. Сохранение происходит по нажатию Enter или кнопки "Save".
- **Удаление проекта**: Кнопка "Delete" вызывает `scheduleDeleteSession(sessionId)`, которая не удаляет проект немедленно, а **переводит его в состояние "удаленного с возможностью отката"**.
- **Откат удаления (Undo)**: После удаления проекта в интерфейсе появляется уведомление "Удалено: [Название]". Пользователь может нажать "Undo", чтобы восстановить проект. Автоматическое скрытие уведомления происходит через `deleteUndoMs` миллисекунд (по умолчанию 5000 мс).
- **Предварительный просмотр**: При наведении курсора на проект в списке вызывается `onPreviewProjectSnapshot(sessionId)`, который загружает последнюю ревизию кода и отображает ее в миниатюре в панели предпросмотра.
- **Сортировка**: Пользователь может сортировать проекты по дате создания, дате обновления или названию.
- **Интеграция с типом диаграммы**: Интерфейс отображает текущий тип диаграммы (например, "Flowchart", "Sequence Diagram") и позволяет его изменить. При обнаружении типа диаграммы в коде (например, через `graph TD`) он подсвечивается как "detected".

#### Интеграция с хуком `useProjects`

Компонент `ChatProjects.tsx` не взаимодействует напрямую с `db.ts` или `store.ts`. Вместо этого он использует **хук `useProjects`**, который является **реактивным адаптером** между UI и хранилищем:

```typescript
export const useProjects = ({ ... }: UseProjectsArgs) => {
  // ... логика синхронизации настроек и сохранения

  const startNewProject = useCallback(async () => {
    await startNewSession({ settings: buildSessionSettings(appState, aiConfig) });
    resetMessages();
    setDiagramIntent(null);
    resetPromptPreview();
    setEditorTab('code');
    setMermaidState(DEFAULT_MERMAID_STATE);
  }, [...]);

  const openProject = useCallback(async (sessionId: string) => {
    await loadSession(sessionId);
  }, [...]);

  // ... другие функции

  return {
    projects: sessions,
    activeProjectId: historySession?.id ?? null,
    startNewProject,
    openProject,
    renameProject,
    removeProject,
    undoRemoveProject,
    deleteUndoMs,
    loadSessionPreview,
    loadSessionSnapshot,
  };
};
```

Хук `useProjects`:
- Слушает изменения в `appState` и `aiConfig` и автоматически сохраняет их в текущий проект с задержкой (debounce 300 мс).
- Синхронизирует состояние редактора (`setMermaidState`, `setEditorTab`) при загрузке проекта.
- Обеспечивает **однонаправленный поток данных**: UI → Хук → Сервис → Хранилище → UI.

## Взаимодействие с другими доменами

Управление Проектами Домен является **центральным узлом** системы, к которому подключены все остальные компоненты:

| Домен | Тип взаимодействия | Описание |
| :--- | :--- | :--- |
| **Редактор Диаграмм Домен** | Data Dependency | При загрузке проекта `useProjects` передает сохраненный `mermaidState` в `useMermaid()`, восстанавливая код редактора. При каждом изменении кода `useProjects` сохраняет новую ревизию. |
| **ИИ-Ассистент Домен** | Data Dependency | История диалога (`messages`) с ИИ сохраняется в `TimeStep` при каждом запросе. При загрузке проекта история восстанавливается в чате. |
| **Предпросмотр Диаграмм Домен** | Service Call | При наведении на проект в списке `ChatProjects` вызывает `loadSessionSnapshot()`, который загружает последнюю ревизию кода и передает ее в `mermaidService` для рендеринга миниатюры. |
| **Инфраструктура Домен** | Tool Support | Использует `localStorage` и `IndexedDB` (инфраструктура хранения), глобальные типы из `types.ts` и константы из `constants.ts` (например, `DEFAULT_MERMAID_STATE`). |

## Принципы проектирования и лучшие практики

1. **Разделение ответственности**: Четкое разделение между слоем доступа к данным (`db.ts`), бизнес-логикой (`store.ts`) и UI (`useProjects.ts`, `ChatProjects.tsx`).
2. **Асинхронность и отказоустойчивость**: Все операции с базой данных асинхронны. Используются `try-catch` блоки и fallback-механизмы (например, `localStorage` как резерв).
3. **Типобезопасность**: Полная типизация на всех уровнях (TypeScript) предотвращает ошибки на этапе компиляции.
4. **Откат действий (Undo)**: Реализация отката удаления проекта — ключевая функция для повышения надежности и пользовательского опыта.
5. **Кэширование и оптимизация**: Использование `useMemo` и `useCallback` в хуке `useProjects` для предотвращения лишних перерисовок.
6. **Минимализм и предсказуемость**: Хук `useProjects` предоставляет только необходимые функции (`startNewProject`, `openProject`, `removeProject` и т.д.), не раскрывая внутреннюю сложность IndexedDB.

## Заключение

Управление Проектами Домен — это **надежный, масштабируемый и пользователь-ориентированный фундамент** всей платформы mermaid-langgraph. Его архитектура демонстрирует лучшие практики современного фронтенд-развития: модульность, типобезопасность, асинхронность и интуитивный пользовательский интерфейс. Благодаря этому домену пользователи могут работать с десятками диаграмм, не опасаясь потери данных, и легко переключаться между проектами, что напрямую повышает продуктивность разработчиков, архитекторов и технических писателей.
