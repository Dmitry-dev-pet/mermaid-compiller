# Документация: Инфраструктура Домен

## Обзор

**Инфраструктура Домен** представляет собой технический фундамент приложения `mermaid-langgraph`, обеспечивающий стабильность, масштабируемость и корректную работу всех бизнес-доменов. В отличие от доменов, реализующих непосредственную пользовательскую логику (редактирование, предпросмотр, ИИ-ассистент), Инфраструктура Домен не содержит бизнес-правил, но является критически важным слоем, отвечающим за сборку, конфигурацию, экспорт, типизацию и мониторинг приложения. Его основная задача — предоставить надежную, предсказуемую и гибкую среду для работы всех компонентов системы.

Домен реализован как набор конфигурационных файлов, сервисов и глобальных типов, которые интегрированы в архитектуру на уровне сборки и базовых сервисов. Он обеспечивает связность между компонентами, стандартизирует взаимодействие с внешними системами и гарантирует единообразие типов и значений по всему приложению.

## Структура и Поддомены

Инфраструктура Домен состоит из четырех взаимосвязанных поддоменов, каждый из которых отвечает за свою техническую область.

### 1. Сборка и Конфигурация

Этот поддомен является ядром инфраструктуры, отвечающим за инициализацию, настройку и запуск сборочной системы Vite. Он определяет, как приложение компилируется, оптимизируется и развертывается как в режиме разработки, так и в продакшене.

**Ключевые файлы:**
- `vite.config.ts` — основной конфигурационный файл Vite.
- `vite-env.d.ts` — типизация переменных окружения.
- `tsconfig.json` — конфигурация TypeScript.
- `eslint.config.js` — конфигурация статического анализа кода.

**Техническая реализация:**
```typescript
// diagram-compiler/vite.config.ts
import path from 'path';
import { defineConfig, loadEnv } from 'vite';
import react from '@vitejs/plugin-react';

export default defineConfig(({ mode }) => {
    const env = loadEnv(mode, '.', '');
    return {
      server: {
        port: 3000,
        host: '0.0.0.0',
      },
      plugins: [react()],

      resolve: {
        alias: {
          '@': path.resolve(__dirname, '.'), // Псевдоним для упрощения импортов
        }
      }
    };
});
```

**Функциональные обязанности:**
- **Псевдонимы путей (Aliases)**: Определяет псевдоним `@` для корневой директории проекта, что позволяет использовать импорты вида `import { AppState } from '@/types'` вместо длинных относительных путей. Это повышает читаемость кода и упрощает рефакторинг.
- **Загрузка переменных окружения**: Использует `loadEnv()` для динамической загрузки переменных из `.env`-файлов, что позволяет легко настраивать поведение приложения для разных сред (разработка, тестирование, продакшен).
- **Интеграция плагинов**: Подключает плагин `@vitejs/plugin-react` для поддержки React-компонентов и TypeScript.
- **Настройка сервера разработки**: Задает порт (`3000`) и хост (`0.0.0.0`), обеспечивая доступ к приложению из локальной сети.
- **Типизация окружения**: Файл `vite-env.d.ts` объявляет типы для переменных окружения (`VITE_PROXY_ENDPOINT`, `VITE_OPEN_ROUTER_ENDPOINT`), что обеспечивает автодополнение и проверку типов в IDE.

**Взаимодействие с другими доменами:**
- **ИИ-Ассистент Домен**: Предоставляет эндпоинты для LLM-провайдеров (`VITE_OPEN_ROUTER_ENDPOINT`, `VITE_PROXY_ENDPOINT`), используемые в `OpenRouterStrategy.ts` и `CliproxyStrategy.ts`.
- **Редактор Диаграмм Домен**: Псевдоним `@` используется для импорта кастомных хуков (`useMermaid`, `useChat`) и утилит (`mermaidPatterns.ts`).
- **Предпросмотр Диаграмм Домен**: Обеспечивает корректную сборку CSS-стилей и ресурсов, необходимых для рендеринга Mermaid-диаграмм.
- **Управление Проектами Домен**: Конфигурация сборки влияет на доступность файлов виртуальных модулей и статических ресурсов, используемых для сохранения проектов.

### 2. Экспорт

Поддомен отвечает за преобразование визуализированных Mermaid-диаграмм в стандартные графические форматы (SVG и PNG) для последующего использования в документах, презентациях и системах документации.

**Ключевой файл:**
- `exportService.ts` — основной сервис, реализующий логику экспорта.

**Техническая реализация:**
Сервис `exportService.ts` реализует сложный алгоритм, который:
1. **Извлекает границы диаграммы**: Анализирует атрибут `viewBox` SVG-элемента или вычисляет его на основе `getBBox()`.
2. **Клонирует и оптимизирует SVG**: Создает чистую копию SVG, устанавливает корректные атрибуты `width`, `height` и `xmlns`, добавляет фон при необходимости.
3. **Инлайнит внешние ресурсы**: Для экспорта в PNG сервис автоматически загружает и встраивает в SVG все внешние изображения (через `fetch`) и CSS-файлы, преобразуя их в `data:` URL. Это критично для корректного отображения диаграммы в PNG без зависимости от внешних серверов.
4. **Конвертирует SVG в PNG**: Использует `canvas` API для рендеринга SVG-контента в битмап и последующего сохранения в формате PNG.
5. **Инициирует скачивание**: Создает временный `<a>`-элемент, генерирует URL для Blob-объекта и инициирует скачивание файла с корректным именем.

**Ключевые константы:**
```typescript
// diagram-compiler/services/exportService.ts
const MAX_CANVAS_DIMENSION = 8192; // Максимальный размер холста
const MAX_INLINE_IMAGES = 24;      // Максимальное количество встраиваемых изображений
const MAX_INLINE_IMAGE_BYTES = 5_000_000; // Максимальный размер одного изображения
const INLINE_FETCH_TIMEOUT_MS = 12_000; // Таймаут загрузки ресурса
```

**Взаимодействие с другими доменами:**
- **Предпросмотр Диаграмм Домен**: Вызывается при нажатии кнопки "Экспорт" в `PreviewHeaderControls.tsx`. Получает текущий SVG-элемент диаграммы и возвращает Blob-объект для скачивания.
- **Инфраструктура Домен (Типизация)**: Использует тип `ExportViewBox` из `types.ts` для строгой типизации границ диаграммы.

### 3. Аналитика и Мониторинг

Поддомен собирает анонимные метрики использования приложения для улучшения продукта, диагностики проблем и понимания поведения пользователей.

**Ключевые файлы:**
- `analyticsService.ts` — основной сервис сбора и отправки данных.
- `api/analytics.ts` — API-интерфейс для отправки событий.

**Техническая реализация:**
Сервис `analyticsService.ts` реализует надежный механизм сбора событий с учетом производительности и конфиденциальности:
- **Сессионный ID**: Генерирует уникальный идентификатор сессии (`sessionId`) при первом запуске и сохраняет его в `localStorage`.
- **Отправка событий**: Использует `navigator.sendBeacon()` для отправки данных в фоновом режиме, что гарантирует доставку даже при закрытии вкладки. В качестве резервного механизма применяет `fetch` с опцией `keepalive`.
- **Отключение аналитики**: Пользователь может отключить сбор данных через `localStorage` (ключ `dc_analytics_disabled`). По умолчанию аналитика отключена для `localhost`.
- **Безопасность**: Все ошибки при отправке данных подавляются, чтобы не нарушать пользовательский опыт.
- **Контекст**: Собирает контекстные данные, такие как выбранный провайдер ИИ, модель, тип диаграммы и язык, что позволяет анализировать предпочтения пользователей.

**Пример события:**
```typescript
trackAnalyticsEvent('click_export_button', {
  provider: 'openrouter',
  model: 'gpt-4o-mini',
  diagramType: 'sequence',
  language: 'en'
});
```

**Взаимодействие с другими доменами:**
- **Все домены**: Вызывается из хуков и компонентов для отслеживания ключевых действий пользователя (например, нажатие кнопки "Автоисправление", выбор модели ИИ, экспорт диаграммы).
- **ИИ-Ассистент Домен**: Отслеживает частоту использования функций генерации и исправления кода.
- **Управление Проектами Домен**: Отслеживает количество созданных и загруженных проектов.

### 4. Типизация и Константы

Этот поддомен является "источником истины" для всех типов данных и глобальных констант в приложении. Он обеспечивает строгую типизацию и согласованность значений по всему кодовому базису, предотвращая ошибки на этапе компиляции.

**Ключевые файлы:**
- `types.ts` — глобальные интерфейсы и типы.
- `constants.ts` — значения по умолчанию и конфигурационные константы.
- `utils/uiTokens.ts` — размеры и стили UI-элементов.
- `utils/uiModes.ts` — стили для различных режимов интерфейса.
- `utils/systemPrompts.ts` — логика работы с системными промптами.

## Взаимодействия и Зависимости

Инфраструктура Домен является **инструментальной поддержкой** для всех остальных доменов. Его зависимости являются односторонними: все бизнес-домены зависят от него, но он не зависит от них.

| Направление зависимости | Описание |
| :--- | :--- |
| **Инфраструктура → Редактор Диаграмм** | Предоставляет псевдонимы путей (`@`) для импорта утилит и хуков, а также конфигурацию сборки, необходимую для работы Vite-плагина `IncludesPlugin`. |
| **Инфраструктура → Предпросмотр Диаграмм** | Обеспечивает корректную сборку CSS-стилей и ресурсов, а также предоставляет типы для управления темой (`AppState.theme`). |
| **Инфраструктура → ИИ-Ассистент** | Передает эндпоинты и ключи API через переменные окружения (`VITE_OPEN_ROUTER_ENDPOINT`, `VITE_PROXY_ENDPOINT`), используемые в `LLMProviderStrategy`. |
| **Инфраструктура → Управление Проектами** | Предоставляет типы (`MermaidState`, `AppState`) и константы для структуры сохраняемых данных. |
| **Предпросмотр → Инфраструктура** | Вызывает сервис `exportService.ts` для экспорта диаграммы в SVG/PNG. |

## Заключение

Инфраструктура Домен — это незаметный, но жизненно важный слой архитектуры `mermaid-langgraph`. Он не привлекает внимания пользователей, но является основой, на которой строится вся функциональность приложения. Его грамотная реализация обеспечивает:

- **Стабильность**: Корректная сборка и конфигурация предотвращают ошибки развертывания.
- **Масштабируемость**: Псевдонимы путей и модульная структура позволяют легко добавлять новые компоненты.
- **Типобезопасность**: Глобальные типы и константы минимизируют баги, связанные с несоответствием типов.
- **Аналитическую прозрачность**: Сбор метрик позволяет принимать обоснованные решения по развитию продукта.
- **Пользовательский опыт**: Надежный экспорт и корректная работа с ресурсами обеспечивают профессиональный результат.

Этот домен демонстрирует лучшие практики современной фронтенд-разработки: разделение ответственности, строгая типизация, конфигурация через окружение и асинхронная, ненавязчивая аналитика. Его архитектура является образцом для подражания в проектах, ориентированных на сложную пользовательскую логику.
