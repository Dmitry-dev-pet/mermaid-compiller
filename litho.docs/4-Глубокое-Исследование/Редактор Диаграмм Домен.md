# Документация: Редактор Диаграмм Домен

## Обзор домена

**Редактор Диаграмм Домен** — это центральный компонент платформы **mermaid-langgraph**, отвечающий за интерактивное редактирование текстового кода диаграмм Mermaid. Он обеспечивает пользователю интуитивную и мощную среду для создания, модификации и управления структурой диаграмм, интегрируя синтаксическую подсветку, специализированные команды вставки и поддержку модульной документации. Домен является основной точкой взаимодействия пользователя с кодом диаграммы и критически важен для повышения продуктивности разработчиков, архитекторов и технических писателей.

Домен реализован как React-приложение на TypeScript и состоит из трех взаимосвязанных поддоменов: **Редактор Кода**, **Команды Редактирования** и **Инлайн-Включение Данных**. Он не содержит собственной бизнес-логики генерации или визуализации, но обеспечивает надежную основу для этих процессов, передавая обработанный код в домены Предпросмотра и ИИ-Ассистента. Его архитектура построена на принципах разделения ответственности, что позволяет легко тестировать, расширять и поддерживать код.

## Поддомены и их реализация

### 1. Редактор Кода

**Редактор Кода** — это ядро домена, реализующее полнофункциональный текстовый редактор для Mermaid-кода с поддержкой Markdown-синтаксиса. Он отвечает за отображение, редактирование и базовый анализ кода диаграммы.

#### Ключевые компоненты и функции

- **`CodeEditorPanel.tsx`**: Основной React-компонент, реализующий пользовательский интерфейс редактора. Он использует библиотеку `react-simple-code-editor` для отображения текста и обеспечивает:
  - **Подсветка строк**: Отображение номеров строк в левой панели с выделением строки с ошибкой (при наличии).
  - **Синхронизация прокрутки**: Связь с компонентом предпросмотра через `onScroll` и `scrollContainerRef` для обеспечения синхронизации скролла.
  - **Поддержка режима только для чтения**: Позволяет временно заблокировать редактирование (например, при генерации кода ИИ).
  - **Кастомная стилизация**: Использует монопроцессорный шрифт `Fira Code` и темную/светлую тему в соответствии с глобальными настройками UI (`uiTokens.ts`).

- **`markdownBlocks.ts`**: Утилита для анализа структуры Markdown-документа. Она определяет, где находятся блоки Mermaid, заключенные в тройные обратные кавычки (```` ```mermaid ``` ````). Ключевые функции:
  - `computeMarkdownBlockScrollTops`: Вычисляет вертикальные позиции (top) каждого блока Mermaid в документе, что необходимо для синхронизации скролла.
  - `resolveActiveMarkdownBlockIndex`: Определяет, какой блок Mermaid находится в зоне видимости при прокрутке, что позволяет подсвечивать соответствующий фрагмент в предпросмотре.

- **`mermaidPatterns.ts`**: Содержит набор регулярных выражений для автоматического определения типа диаграммы. Это позволяет системе динамически адаптировать поведение (например, подсказки, валидацию) в зависимости от типа диаграммы (flowchart, sequence, classDiagram и т.д.). Пример:
  ```ts
  export const DIAGRAM_TYPE_PATTERNS: Array<{ pattern: RegExp; type: DiagramType }> = [
    { pattern: /^(flowchart|graph)\b/i, type: 'flowchart' },
    { pattern: /^sequenceDiagram\b/i, type: 'sequence' },
    { pattern: /^classDiagram\b/i, type: 'class' },
    // ... другие типы
  ];
  ```

- **`mermaidFrontmatter.ts`**: Обеспечивает поддержку YAML-фронтматтера для управления глобальными настройками диаграммы. Он позволяет вставлять метаданные в начало документа, например:
  ```yaml
  ---
  config:
    theme: dark
    look: handDrawn
  ---
  ```
  Функции `updateFrontmatterConfigKey`, `extractFrontmatterConfigValue` и `removeFrontmatterConfigKey` позволяют программно читать, обновлять и удалять эти настройки, обеспечивая консистентность между редактором и предпросмотром.

#### Поток обработки кода
Пользователь вводит код → Редактор отображает его с подсветкой синтаксиса → `markdownBlocks.ts` выделяет блоки Mermaid → `mermaidPatterns.ts` определяет тип диаграммы → `mermaidFrontmatter.ts` извлекает метаданные → Результат передается в `mermaidService.ts` для валидации и рендеринга.

### 2. Команды Редактирования

**Команды Редактирования** — это уникальная функциональность, позволяющая пользователю управлять стилями и поведением диаграммы через специальные комментарии, которые не являются частью стандартного синтаксиса Mermaid. Эти команды обрабатываются на стороне редактора и преобразуются в корректный Mermaid-код для рендеринга.

#### Ключевые команды и реализация

- **Темы (`inlineThemeCommand.ts`)**: Позволяет задавать тему диаграммы (например, `%%{ theme: dark }%%`). Реализация:
  - `extractInlineThemeCommand`: Ищет команду в коде и в фронтматтере, возвращает код без команды и значение темы.
  - `setInlineThemeCommand`: Вставляет команду в фронтматтер или удаляет ее, если тема `null`.
  - `applyInlineThemeCommand`: Применяет тему к коду, возвращая обновленный код и тему.

- **Направления (`inlineDirectionCommand.ts`)**: Управляет ориентацией диаграмм (например, `%%{ direction: LR }%%` для горизонтального направления). Реализация сложнее, так как требует изменения структуры Mermaid-кода:
  - `extractInlineDirectionCommand`: Анализирует код, ищет команду и определяет направление из заголовка диаграммы (например, `flowchart LR`).
  - `setInlineDirectionCommand`: Вставляет или обновляет директиву `direction` в заголовке диаграммы (для `flowchart`, `graph`) или в отдельной строке (для `classDiagram`, `stateDiagram`).
  - Использует `mermaidDirectives.ts` для вставки директивы в правильное место после всех комментариев.

- **Внешний вид (`inlineLookCommand.ts`)**: Управляет стилем отображения (например, `%%{ look: handDrawn }%%`). Реализация аналогична команде темы:
  - `extractInlineLookCommand`: Извлекает значение `look` из фронтматтера или комментария.
  - `setInlineLookCommand`: Вставляет или удаляет настройку `look` в фронтматтер.
  - `applyInlineThemeAndLookCommands`: Комбинирует обработку темы и внешнего вида в одном вызове.

#### Преимущества подхода
Этот подход позволяет:
- **Сохранять совместимость**: Команды не нарушают стандарт Mermaid, так как являются комментариями.
- **Обеспечивать гибкость**: Пользователь может легко переключать темы и направления без изменения основного кода.
- **Поддерживать модульность**: Настройки могут быть встроены в Markdown-документы и сохранены в проектах.

### 3. Инлайн-Включение Данных

**Инлайн-Включение Данных** — это функция, ориентированная на технических писателей, позволяющая создавать модульную и повторно используемую документацию. Она поддерживает синтаксис `@@include('path/to/diagram.mmd')` для встраивания содержимого внешних Mermaid-файлов прямо в Markdown-документ.

#### Реализация и интеграция

- **`IncludesPlugin.ts`**: Этот плагин является частью **Инфраструктуры Домена** и работает на этапе сборки Vite. Он не является частью фронтенд-кода редактора, но его функциональность критически важна для полного понимания домена.
- **Роль Редактора**: Редактор Кода (`CodeEditorPanel.tsx`) и утилиты (`markdownBlocks.ts`) отвечают за **отображение** синтаксиса `@@include` в редакторе. Они не разрешают пути и не читают файлы — это делает сборщик Vite.
- **Пользовательский опыт**: Пользователь видит в редакторе код `@@include('...')` как обычный текст. При сохранении и сборке проекта Vite-плагин `IncludesPlugin.ts` автоматически заменяет эту строку на содержимое указанного файла `.mmd`, и рендерер в предпросмотре отображает итоговую диаграмму.

#### Бизнес-ценность
Этот механизм позволяет:
- **Создавать библиотеки диаграмм**: Одна диаграмма может быть включена в несколько документов.
- **Упрощать поддержку**: Изменение в одном файле `.mmd` автоматически обновляется во всех документах.
- **Собирать сложную документацию**: Технический писатель может создавать большие документы, разбивая их на логические модули.

## Взаимодействие с другими доменами

Редактор Диаграмм Домен является центральным узлом в архитектуре системы и тесно интегрирован с другими доменами:

1. **Связь с Предпросмотром Диаграмм Доменом**:
   - **Направление**: `Редактор → Предпросмотр`.
   - **Механизм**: При каждом изменении кода (`onValueChange` в `CodeEditorPanel.tsx`) редактор передает обновленный текст в `mermaidService.ts` (из домена Предпросмотра) для валидации и рендеринга.
   - **Синхронизация**: `markdownBlocks.ts` предоставляет данные о позициях блоков, которые используются `useScrollSync.ts` и `useMarkdownMermaidOffsets.ts` для синхронизации прокрутки между редактором и предпросмотром. Это создает ощущение единого документа.

2. **Связь с ИИ-Ассистентом Доменом**:
   - **Направление**: `ИИ-Ассистент → Редактор`.
   - **Механизм**: После того как LLM-стратегия (`OpenRouterStrategy.ts`) генерирует или исправляет код, `llmService.ts` вызывает `onValueChange` редактора, вставляя новый код. Редактор не анализирует ответ ИИ — он просто отображает его.
   - **Поддержка автоисправления**: Команды редактирования (`inlineThemeCommand.ts`, `inlineDirectionCommand.ts`) обеспечивают, что код, возвращаемый ИИ, может содержать команды, которые будут корректно обработаны при последующем рендеринге.

3. **Зависимость от Инфраструктуры Домена**:
   - **Сборка**: Конфигурация Vite (`vite.config.ts`) регистрирует виртуальные модули и плагины, необходимые для работы `@@include`.
   - **Типизация**: Глобальные типы (`types.ts`, `uiModes.ts`) определяют типы диаграмм (`DiagramType`) и режимы UI, которые используются в `mermaidPatterns.ts` и `CodeEditorPanel.tsx`.
   - **Экспорт**: Редактор не отвечает за экспорт, но его код является источником данных для `exportService.ts`, который экспортирует SVG/PNG из предпросмотра.

## Технические особенности и архитектурные решения

- **Функциональный подход**: Все утилиты (`markdownBlocks.ts`, `mermaidPatterns.ts`) написаны в функциональном стиле, без состояния. Это делает их легко тестируемыми и независимыми от React-компонентов.
- **Изоляция ответственности**: Каждая команда (тема, направление, внешний вид) реализована в отдельном файле, что соответствует принципу Single Responsibility.
- **Безопасность**: При обработке команд используется строгая валидация (`normalizeThemeToken`, `normalizeDirection`) для предотвращения внедрения вредоносного кода.
- **Производительность**: Для больших документов используется ленивая обработка (например, `computeMarkdownBlockScrollTops` вызывается только при изменении кода, а не при каждой прокрутке).
- **Поддержка Markdown**: Редактор не является полноценным Markdown-редактором, но он корректно обрабатывает блоки Mermaid внутри Markdown-документов, что делает его идеальным инструментом для технической документации.

## Заключение

Редактор Диаграмм Домен — это не просто текстовый редактор, а продуманная система, которая превращает Mermaid из простого языка разметки в мощный инструмент для создания профессиональной документации. Его сильные стороны — это **интуитивность** (через команды редактирования), **модульность** (через `@@include`) и **надежность** (через строгую типизацию и изоляцию компонентов). Он обеспечивает пользователю полный контроль над кодом диаграммы, позволяя сосредоточиться на архитектуре, а не на синтаксисе. Его успешная интеграция с ИИ-ассистентом и предпросмотром создает уникальный рабочий процесс, который значительно повышает продуктивность команд, работающих с архитектурными диаграммами.
