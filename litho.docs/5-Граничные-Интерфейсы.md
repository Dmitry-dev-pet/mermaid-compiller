# System Boundary Interface Documentation

This document describes the system's external invocation interfaces, including CLI commands, API endpoints, configuration parameters, and other boundary mechanisms.

## API Interfaces

### POST /api/analytics

**Description**: Отправка аналитических данных о действиях пользователя в приложении (генерация диаграмм, экспорт, редактирование). Используется сервисом analytics.ts для отправки событий в внешний сервис аналитики.

**Source File**: `/diagram-compiler/api/analytics.ts`

**Request Format**: JSON { eventType: string, payload: object, timestamp: number }

**Response Format**: JSON { success: boolean, message: string }

**Authentication**: Не требуется (локальные данные, но может использовать токен сессии)

### POST /api/llm/generate

**Description**: Продуктовый интерфейс для вызова ИИ-провайдера (например, OpenRouter) для генерации или улучшения диаграмм Mermaid на основе текстового запроса. Вызывается через llmService и LLMProviderStrategy.

**Source File**: `/diagram-compiler/services/llmService.ts`

**Request Format**: JSON { prompt: string, model: string, diagramType: 'flowchart' | 'sequence' | 'mindmap', context: string }

**Response Format**: JSON { diagramCode: string, metadata: { modelUsed: string, confidence: number }, errors: string[] }

**Authentication**: Bearer токен (внешний ключ API, хранится в localStorage или переменных окружения)

### POST /api/export

**Description**: Экспорт диаграммы Mermaid в формате SVG или PNG на стороне сервера. Может использоваться для генерации высококачественных изображений, требующих рендеринга вне браузера.

**Source File**: `/diagram-compiler/services/exportService.ts`

**Request Format**: JSON { mermaidCode: string, format: 'svg' | 'png', theme: 'default' | 'dark', width: number, height: number }

**Response Format**: Binary (image/jpeg, image/svg+xml) или base64-encoded string

**Authentication**: Bearer токен (аутентификация сессии)

### POST /api/history/save

**Description**: Сохранение текущего состояния проекта диаграммы в историю (IndexedDB на клиенте, но интерфейс может быть расширен до серверной синхронизации).

**Source File**: `/diagram-compiler/services/history/store.ts`

**Request Format**: JSON { projectId: string, mermaidCode: string, title: string, timestamp: number, metadata: object }

**Response Format**: JSON { success: boolean, historyId: string }

**Authentication**: Bearer токен (если реализована серверная синхронизация)

### GET /api/history/list

**Description**: Получение списка сохранённых проектов диаграмм из истории пользователя (данные хранятся в IndexedDB, но API обеспечивает модель доступа).

**Source File**: `/diagram-compiler/services/history/store.ts`

**Request Format**: null

**Response Format**: JSON [ { id: string, title: string, updatedAt: number, diagramType: string } ]

**Authentication**: Bearer токен (если реализована серверная синхронизация)

## Integration Suggestions

### API Integration

Интеграция с внешними ИИ-провайдерами, такими как OpenRouter, Anthropic или OpenAI. Рекомендуется использовать централизованный прокси-сервис для управления API-ключами и ограничением доступа.

**Example Code**:

```
const llmResponse = await fetch('/api/llm/generate', {
  method: 'POST',
  headers: { 'Authorization': `Bearer ${localStorage.getItem('api_key')}` },
  body: JSON.stringify({ prompt: 'Нарисуй flowchart с двумя узлами', model: 'claude-3-opus' })
});
```

**Best Practices**:

- Не храните API-ключи в коде — используйте переменные окружения на сервере или зашифрованные токены в localStorage с подписью.
- Ограничивайте частоту вызовов (rate limiting) для предотвращения злоупотреблений.
- Валидируйте входные параметры prompt и diagramType на серверной стороне.
- Обрабатывайте ошибки ответа с возвратом человеко-понятных сообщений, а не сырого ответа от API.

### CLI Integration

Хотя текущая система не имеет CLI, рекомендуется разработать утилиту командной строки для автоматизации сборки документации, экспорта диаграмм и проверки синтаксиса Mermaid в пакетном режиме.

**Example Code**:

```
mermaid-cli export --input diagrams/flowchart.mmd --output output/flowchart.svg --format svg
```

**Best Practices**:

- Создайте CLI на основе Node.js с использованием Commanders.js или Oclif.
- Реализуйте поддержку @@include-синтаксиса из документации VitePress для встраивания внешних файлов.
- Добавьте проверку валидности Mermaid-кода перед экспортом.
- Интегрируйте с CI/CD для автоматического обновления документации при изменении диаграмм.

### VitePress Plugin Integration

Интеграция с VitePress через плагины для автоматического рендеринга диаграмм в документации. Текущий проект уже использует virtual:mermaid-config для конфигурации.

**Example Code**:

```
'virtual:mermaid-config' может быть расширен для динамической передачи пользовательских тем и настроек безопасности через .md файлы с frontmatter.
```

**Best Practices**:

- Используйте frontmatter в Markdown-файлах для указания темы ({ theme: 'dark' }) и уровня безопасности ({ securityLevel: 'strict' }).
- Настройте автоматическое обнаружение и пересборку диаграмм при изменении внешних файлов, указанных через @@include.
- Настройте плагин для генерации карты диаграмм (diagram map) на странице документации для навигации.
- Синхронизируйте темы между приложением и документацией для единообразия.

### Frontend State Management

Интеграция с хуками и контекстами React для управления состоянием редактора, предпросмотра и истории. Рекомендуется централизовать состояние диаграмм в одном store.

**Example Code**:

```
const { mermaidCode, setMermaidCode } = useMarkdownMermaid();
useEffect(() => { saveToHistory(mermaidCode); }, [mermaidCode]);
```

**Best Practices**:

- Обеспечьте единый источник правды (single source of truth) для состояния диаграммы через custom hook useDiagramState().
- Синхронизируйте состояние между редактором и предпросмотром через реактивные подписки (Reactive State).
- Используйте Web Workers для тяжелых операций парсинга Mermaid, чтобы не блокировать основной поток.
- Добавьте откаты и управление версиями через буфер изменений (Undo/Redo Stack).
